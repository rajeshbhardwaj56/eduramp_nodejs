# Node.js + Prisma ORM + PostgreSQL — Step-by-Step Guide

A REST API built in 16 steps: **user authentication (register / login / JWT)** and
**products CRUD** with ownership rules, validation, pagination, and error handling.

| Tool | Version | Job |
| --- | --- | --- |
| Node.js | 22.18+ | Runs JavaScript on the server |
| Express | 5 | Web framework: routes and middleware |
| Prisma ORM | 7.10 | Talks to the database with JavaScript instead of raw SQL |
| PostgreSQL | 14+ | The database |
| bcryptjs | 3 | Hashes passwords |
| jsonwebtoken | 9 | Creates and checks login tokens (JWT) |
| Zod | 4 | Validates request data |

---

## How a request flows through the app

```
Client (curl / Postman / browser)
   │  POST /api/products   Authorization: Bearer <token>   { "name": ..., "price": ... }
   ▼
app.js ── helmet, cors, express.json(), morgan          (global middleware)
   ▼
routes/product.routes.js
   ▼
middleware/auth.js       authenticate → checks the JWT, loads req.user
   ▼
middleware/validate.js   validate(schema) → checks body/params/query with Zod
   ▼
controllers/product.controller.js   business logic
   ▼
lib/prisma.js            Prisma Client → SQL → PostgreSQL
   ▼
JSON response   ── or, if anything throws ──►  middleware/errorHandler.js → JSON error
```

# Building it step by step

## Step 1 — Install PostgreSQL and create a project

You need PostgreSQL running. Pick one:

```bash
# macOS (Homebrew)
brew install postgresql@16 && brew services start postgresql@16

# Any OS with Docker
docker run --name pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:16
```

Create the project and switch it to ES modules (`import` / `export`):

```bash
mkdir nodejs_prisma && cd nodejs_prisma
npm init -y
npm pkg set type=module
```

## Step 2 — Install packages

```bash
npm install express@5 @prisma/client@7.10.1 @prisma/adapter-pg@7.10.1 pg \
  bcryptjs jsonwebtoken zod dotenv cors helmet morgan
npm install -D prisma@7.10.1
```

- `prisma` (dev) is the **CLI**: migrations, generate, studio.
- `@prisma/client` is the **runtime** your code uses to query.
- `@prisma/adapter-pg` + `pg`: since Prisma 7, Prisma connects through a **driver adapter**
  (here `node-postgres`).

> Pin `7.10.1` on purpose: npm's `latest` tag currently points to a Prisma 8 release candidate.

## Step 3 — Initialise Prisma

```bash
npx prisma init --datasource-provider postgresql
```

This creates:

- `prisma/schema.prisma` — your data models
- `prisma7.config.ts` — CLI settings (where the schema, migrations and DB URL are)
- `.env` — environment variables

> **Prisma 7.10 note:** the config file is named `prisma7.config.ts` (the plain
> `prisma.config.ts` name is reserved for Prisma 8). `init` may also add AI-editor
> folders (`.claude/`, `.agents/`, `.windsurf/`, `skills-lock.json`); they are optional.

Replace `prisma7.config.ts` with:

```ts
import 'dotenv/config';                         // the CLI does NOT read .env by itself
import { defineConfig, env } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
    seed: 'node prisma/seed.js',                // used by `npx prisma db seed`
  },
  datasource: {
    url: env('DATABASE_URL'),
  },
});
```

## Step 4 — Environment variables

`.env` (never commit this file — it's in `.gitignore`):

```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/prisma_store?schema=public"
PORT=4000
NODE_ENV=development
JWT_SECRET="a-long-random-string-at-least-32-characters"
JWT_EXPIRES_IN="1d"
```

Connection string anatomy: `postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public`.
If the password has special characters (`@`, `#`, `/`), URL-encode them.

Generate a strong secret:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Then create **`src/config/env.js`**: it validates the variables with Zod at startup, so a
missing `JWT_SECRET` stops the app immediately with a clear message.

## Step 5 — Design the schema

**`prisma/schema.prisma`**

```prisma
generator client {
  provider     = "prisma-client"           // Prisma 7 generator
  output       = "../src/generated/prisma" // required: where the client is written
  moduleFormat = "esm"
}

datasource db {
  provider = "postgresql"                  // URL comes from prisma7.config.ts
}

enum Role {
  USER
  ADMIN
}

model User {
  id        Int       @id @default(autoincrement())
  name      String
  email     String    @unique
  password  String
  role      Role      @default(USER)
  products  Product[]
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  @@map("users")
}

model Product {
  id          Int      @id @default(autoincrement())
  name        String
  description String?
  price       Decimal  @db.Decimal(10, 2)
  stock       Int      @default(0)
  ownerId     Int
  owner       User     @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@index([ownerId])
  @@map("products")
}
```

Teaching points:

- `@id @default(autoincrement())` → `SERIAL PRIMARY KEY`.
- `@unique` on email → the database itself blocks duplicate accounts.
- `String?` → the column can be `NULL`.
- **One-to-many relation:** `User.products` ↔ `Product.owner`. `ownerId` is the real
  foreign-key column; `owner` / `products` exist only in Prisma for easy joins.
- `onDelete: Cascade` → deleting a user deletes their products.
- `Decimal(10, 2)` for money. `Float` would give rounding errors like `0.1 + 0.2 = 0.30000000000000004`.
- `@@map("users")` → table name in the DB; the model name in code stays `User`.

## Step 6 — Run the first migration

```bash
npx prisma migrate dev --name init
```

This (1) creates the `prisma_store` database if it doesn't exist, (2) writes the SQL to
`prisma/migrations/<timestamp>_init/migration.sql`, and (3) runs it. Open that SQL file
with your students — it shows exactly what Prisma did.

> **Prisma 7 change:** `migrate dev` no longer runs `prisma generate` or the seed for you.

**Every time you change `schema.prisma`, run both:**

```bash
npx prisma migrate dev --name <what-changed>   # update the database
npx prisma generate                            # update the client code
```

## Step 7 — Create the Prisma Client (one instance only)

**`src/lib/prisma.js`**

```js
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../generated/prisma/client.ts';
import { env } from '../config/env.js';

const adapter = new PrismaPg({ connectionString: env.DATABASE_URL });

export const prisma = new PrismaClient({
  adapter,
  omit: { user: { password: true } },   // never return password hashes by accident
});
```

- Each `PrismaClient` opens a connection pool — create **one** and import it everywhere.
- The generated client is TypeScript (`client.ts`). Node 22.18+ runs `.ts` files
  directly, so a plain-JavaScript project can import it with no build step.
- The global `omit` hides `password` from every user query. Login opts back in with
  `omit: { password: false }`.

## Step 8 — Helpers: `ApiError` and JWT

- **`src/utils/ApiError.js`** — an `Error` that carries a status code:
  `throw ApiError.notFound('Product not found')`.
- **`src/utils/jwt.js`** — `signAccessToken(user)` and `verifyAccessToken(token)`.
  The user's id goes in the token's `sub` (subject) claim and the role in the payload.

> A JWT is **signed, not encrypted** — anyone can decode it (try https://jwt.io).
> Never put secrets in it. The signature only proves the server issued it.

## Step 9 — Middleware

**`src/middleware/validate.js`** — `validate(schema)` checks `{ body, params, query }` with
Zod. On failure it returns `400` with a list of field errors. On success the cleaned,
type-converted values are put on `req.validated` (Express 5 makes `req.query` read-only).

**`src/middleware/auth.js`**

- `authenticate` reads `Authorization: Bearer <token>`, verifies it, loads the user from
  the database, and sets `req.user`. No/invalid/expired token → `401`.
- `authorize('ADMIN')` runs after `authenticate` and returns `403` if the role doesn't match.

**`src/middleware/errorHandler.js`** — one place that turns every error into JSON:

| Error | Response |
| --- | --- |
| `ApiError` | its own status code + message |
| Prisma `P2002` (unique constraint) | 409 Conflict |
| Prisma `P2025` (record not found) | 404 |
| Prisma `P2003` (foreign key) | 400 |
| Invalid JSON body | 400 |
| Anything else | 500 (stack trace only in development) |

> **Express 5 bonus:** errors thrown inside `async` handlers are passed to the error
> handler automatically. In Express 4 you needed `try/catch` or an `asyncHandler` wrapper.

**401 vs 403:** 401 = "who are you?" (not logged in). 403 = "I know who you are, but no".

## Step 10 — Validation schemas

- **`src/validators/auth.schema.js`** — email is trimmed and lower-cased *before* being
  checked, so `" Bob@Mail.com "` and `"bob@mail.com"` are the same account. Password:
  8–72 characters with a letter and a number (bcrypt ignores bytes after 72).
- **`src/validators/product.schema.js`** — `z.coerce.number()` converts URL text like
  `"5"` into numbers. Price must be positive with at most 2 decimals.

> **Bug worth showing students:** if `stock` had `.default(0)` in the shared field list,
> `.partial()` for updates would still apply the default — and every update without
> `stock` would silently reset it to 0. That's why the default is added only in
> `createProductSchema`.

## Step 11 — Authentication flow

**`src/controllers/auth.controller.js`** and **`src/routes/auth.routes.js`**

```
REGISTER  POST /api/auth/register
  validate → email taken? (409) → bcrypt.hash(password) → prisma.user.create → JWT → 201

LOGIN     POST /api/auth/login
  validate → find user (with password) → bcrypt.compare → JWT → 200
  wrong email OR wrong password → the same "Invalid email or password" (401)

ME        GET /api/auth/me        (Authorization: Bearer <token>)
  authenticate → return req.user (+ product count)
```

Security points to discuss:

1. **Never store plain passwords.** bcrypt adds a random salt and is deliberately slow.
2. **Same error for unknown email and wrong password**, so attackers can't find out which
   emails are registered. A dummy hash is compared when the user doesn't exist so both
   cases take the same time.
3. **The DB unique index is the real guarantee.** The `findUnique` check gives a friendly
   message; the `P2002` handler covers two sign-ups arriving at the same moment.
4. **Logout with JWTs** happens on the client: delete the token. (Server-side logout needs
   refresh tokens or a block-list — a good follow-up lesson.)

## Step 12 — Products CRUD

**`src/controllers/product.controller.js`** and **`src/routes/product.routes.js`**

| Method | URL | Auth | Prisma call |
| --- | --- | --- | --- |
| GET | `/api/products` | public | `findMany` + `count` in `$transaction` |
| GET | `/api/products/:id` | public | `findUnique` |
| POST | `/api/products` | logged in | `create` (owner = `req.user.id`) |
| PATCH | `/api/products/:id` | owner or admin | `update` |
| DELETE | `/api/products/:id` | owner or admin | `delete` → 204 |

List query options: `?page=1&limit=10&search=desk&minPrice=10&maxPrice=500&sortBy=price&order=asc`

Prisma features this shows:

- **Filtering:** `contains` + `mode: 'insensitive'` (case-insensitive search), `OR`, `gte` / `lte`.
- **Pagination:** `skip` + `take`.
- **Sorting:** `orderBy: { [sortBy]: order }` — safe because Zod only allows known field names.
- **Relations:** `include: { owner: { select: { id: true, name: true } } }` returns the
  owner without their email.
- **Transactions:** `prisma.$transaction([...])` runs the page query and count together.
- **Ownership:** the controller loads the product first; if `ownerId !== req.user.id` and
  the user isn't an admin → 403.

> `price` comes back as a **string** (`"249.99"`). Prisma uses a `Decimal` type to keep
> money exact, and JSON has no decimal type. The client can convert it for display.

## Step 13 — Wire up the app

**`src/app.js`** — order matters: global middleware → routes → `notFound` → `errorHandler`
(the error handler must be last).

**`src/server.js`** — connects to the DB first (fails fast if Postgres is down), starts
listening, and on `Ctrl+C` closes the server and disconnects Prisma cleanly.

**`src/routes/user.routes.js`** — `GET /api/users`, admin only, shows `authorize('ADMIN')`
and `_count` (number of products per user).

Scripts in `package.json`:

```json
"dev": "node --watch src/server.js",
"start": "node src/server.js",
"postinstall": "prisma generate",
"db:migrate": "prisma migrate dev",
"db:seed": "prisma db seed",
"db:studio": "prisma studio",
"db:reset": "prisma migrate reset && prisma db seed"
```

`node --watch` restarts on file changes (built into Node — no nodemon needed).

## Step 15 — Run and test

```bash
npm run dev
```

**Option A:** open `api.http` in VS Code with the *REST Client* extension and click
"Send Request" on each block, top to bottom (the login token is captured automatically).

**Option B:** curl

```bash
# Register
curl -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Bob","email":"bob@example.com","password":"secret123"}'

# Login and keep the token
TOKEN=$(curl -s -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"bob@example.com","password":"secret123"}' | node -pe 'JSON.parse(require("fs").readFileSync(0)).data.token')

# Create
curl -X POST http://localhost:4000/api/products \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"Standing Desk","price":249.99,"stock":5}'

# List / read
curl "http://localhost:4000/api/products?search=desk&sortBy=price&order=asc"
curl http://localhost:4000/api/products/1

# Update (only the fields you send)
curl -X PATCH http://localhost:4000/api/products/1 \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{"stock":10}'

# Delete
curl -X DELETE http://localhost:4000/api/products/1 -H "Authorization: Bearer $TOKEN"
```

**Option C:** Postman — import the curl commands, or add a collection variable `token`.

Things to try in class: no token (401), someone else's product (403), `?limit=500` (400),
`/api/products/abc` (400), duplicate email (409), broken JSON (400).

## Response format

Success:

```json
{ "success": true, "data": { ... }, "meta": { "page": 1, "limit": 10, "total": 42, "totalPages": 5 } }
```

Error:

```json
{ "success": false, "message": "Validation failed",
  "details": [{ "field": "price", "in": "body", "message": "Price must be greater than 0" }] }
```

## Common problems

| Symptom | Fix |
| --- | --- |
| `Can't reach database server` | Postgres isn't running, or host/port in `DATABASE_URL` is wrong |
| `Authentication failed against database server` | Wrong user/password in `DATABASE_URL` |
| `P1010: User was denied access` / `role "postgres" does not exist` | Homebrew Postgres has no `postgres` user (only your Mac username). Use your Mac username with no password in `DATABASE_URL`, or create the user: `psql -d postgres -c "CREATE ROLE postgres WITH LOGIN SUPERUSER PASSWORD 'postgres';"` |
| `Cannot find module '.../generated/prisma/client.ts'` | Run `npx prisma generate` |
| `No seed command configured` | Prisma read a different config file — Prisma 7.10 uses `prisma7.config.ts` |
| `Invalid environment variables: JWT_SECRET` | Secret missing or shorter than 32 characters |
| Code doesn't see a new column | Run `npx prisma migrate dev --name ...` **and** `npx prisma generate` after editing the schema |
| `ERR_UNKNOWN_FILE_EXTENSION ".ts"` | Node is older than 22.18 — upgrade Node |
